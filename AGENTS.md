# AGENTS.md

## Fast Start (avoid destructive mistakes)

- Use `make` only for first-time setup: it copies `.env.example` -> `.env`, `compose.override.yaml.example` -> `compose.override.yaml`, `eternaltwin/etwin.toml.example` -> `eternaltwin/etwin.toml`, regenerates RSA keys, and runs `migrate:fresh --seed`.
- For normal day-to-day work, use `make docker-start` / `make docker-watch` and avoid re-running `make` unless you want setup/reset behavior.
- `make compile-games` requires running containers (`kadokadeo_app` and `kadokadeo_front`) because it uses `docker exec`.

## Repo Shape

- Main app is Laravel + Vue in this root.
- `resources/hx/` = Haxe game sources; `resources/js/games/*.js` = Haxe-generated JS intermediates (tracked); `public/gamesdata/*` = bundled runtime artifacts + `manifest.json`.
- `eternaltwin/` is a separate local service package used by Docker (`yarn etwin`). Treat it as its own boundary.

## Build and Verification Commands

- Frontend dev: `npm run dev`.
- Frontend lint/format (JS/Vue only): `npm run lint`, `npm run format` (operate on `resources/js`).
- Production build: `npm run build` (installs Haxe libs, compiles all games, bundles games, then Vite build).
- Game bundle only: `make compile-games`.
- Backend tests: `docker exec kadokadeo_app php artisan test` (configured for SQLite in-memory via `phpunit.xml`).
- Static analysis: `docker exec -w /www kadokadeo_app vendor/bin/phpstan analyse --memory-limit=2G` (Larastan level 5, in CI; the old errors are in `phpstan-baseline.neon`: new code adds none).
- DB sync/reset in Docker context: `make sync-database`, `make reset-database`.

## Game Pipeline Gotchas

- Do not hand-edit generated files in `resources/js/games/*.js` or `public/gamesdata/*.js`; edit Haxe in `resources/hx/games/*` then rebuild.
- Add/remove a game in both `compile.hxml` and `compile-dev.hxml`.
- `resources/js/games/build-games.mjs` bundles **every** non-`tmp*.js` file in `resources/js/games`; stale JS files are still shipped unless removed.
- `build-games.mjs` also archives the previous version of every bundle that changed in `storage/app/game-builds` (replays are played by the version they were recorded with, see `.opencode/skills/replay-system/SKILL.md`): never delete that folder; `GAME_BUILDS=off` skips it. Currently off on the Laravel side (`SiteSettings::$game_builds_enabled`, the production wipes `storage/` at each deploy): runs remember no version, replays use the current bundle.
- Bundles are minified ES modules that do **not** put the game classes on `window`: `resources/js/games/builds/bundle.mjs` gives them once through the default export (`format: 'esm'` in `manifest.json` / the archive, `gamedata.module`); `useGame.js` imports the bundle with a random URL fragment (a module of its own). Archived bundles built before (classic scripts) still put their classes on `window`. Source maps go to `storage/app/game-sourcemaps` (not public).
- Anti-cheat (client): outside the daily game the gameplay RNG is stirred every frame by the frame, the inputs and the time of each input in its frame (`Seed.stir`, replay v4 « phases », see `.opencode/skills/determinism/SKILL.md`); input events made by a script (`isTrusted` false) are ignored (`kac.Natives`, browser functions snapshotted at page load by `resources/js/anticheat/natives.js`). In a live game `kac.Integrity` freezes the prototypes of the Haxe classes (methods the game assigns to instances, found by the bundler, become accessors; emergency switch: Haxe define `-D kado_no_freeze`) and reports what a page script did in the `ac` mask (`App\Enums\AntiCheatBit`: hard bits mark the run as cheated, soft bits `AntiCheatSettings::$soft_bits` go to the admin queue, ignored bits `$ignored_bits` (default: browser functions replaced, untrusted inputs, frequent on mobile) are only kept on the run).
- Anti-cheat (server): every finished run is evaluated by `App\Services\SuspicionService` (new record of the game, replay longer than the real time, soft `ac` bits; a high score alone is not flagged) into the admin queue « Modération > Runs suspectes » (`run_flags`, nothing sanctioned automatically). Per-game move analyzers run inside the replay verifier: `resources/js/replay-verifier/analyzers/<game_key>.mjs` (see its README: Binary, Kaskade 2, Atlanteine, Autrement, Cooking Lili, Flushee, Tubulo, Xian-Xiang; provisional, bots only: Aqua Splash, Electrolink, Memopsy, Paradice, Razor, Toy Maniak; not every one looks at the best move: Memopsy pairs found blind, Toy Maniak an auto-player's aim, Atlanteine instant inputs; new analyzer: `.opencode/skills/replay-analyzer/SKILL.md`), thresholds by game in `AntiCheatSettings::$analysis_games` (admin « Paramètres > Anti-triche »), calibration with `php artisan kado:replays:analyze <game>` before `$analysis_flag`. The replays of the runs that count are replayed on the server (`App\Jobs\VerifyRunReplay`, `resources/js/replay-verifier/verify.mjs`: Node 22+ and Chrome, `KADO_REPLAY_VERIFIER_NODE` / `_BROWSER` in `config/kado.php`, turned on in `AntiCheatSettings`). Without a system Chrome/Chromium, `browser.mjs` downloads chrome-headless-shell (`@puppeteer/browsers`) into `storage/app/replay-verifier/browser`; it still needs Chrome's system libraries and a font. The scripts end themselves after `AntiCheatSettings::$verifier_timeout` and kill the whole process group of their browser (`cdp.mjs`); a browser left by a killed script is killed by `kado:replay-verifier:reap` (every 5 minutes, by its `kado-verifier-*` profile). Admin page « Paramètres > Vérificateur de replays »: stats and history of the verifications (`replay_verifications`, the verified ones pruned after 30 days), replays in a modal (`RunReplayController`, Vite entry `resources/js/replay-player.js`), diagnostic of a server (`check.mjs`).
- Exact math (replay v5): `Math.sin/cos/atan2/pow/acos/exp/log` of the bundles are pointed by esbuild to `resources/js/games/builds/exact-math.mjs` (fdlibm in plain JS: the browsers' differ in the last bit between Chrome x86 / ARM / Safari, and replays are chaotic). `kado.ExactMath` turns it on for a live game and the v5 replays; older replays keep the browser's functions. Another transcendental function used by a game's logic must be added there (check it against Java `StrictMath`).
- In the replay verifier (`params.headless`, `KadoKadeoManager.headless`) the stage is not drawn and `mt.bumdum.Plasma` draws nothing (software WebGL: Cooking Lili / Travoltax took minutes); a per-frame effect that the game never reads can skip itself the same way.
- Runtime game loading depends on DB game name -> `game_key` mapping (`App\Models\Game::getGameKeyAttribute`), so filenames must match sanitized lowercase game names (e.g. `Opalus 2` -> `opalus2.js`).

## Backend/API Conventions That Matter

- API auth is enforced per-controller with `HasMiddleware`/`Middleware` (not one global auth group in `routes/api.php`).
- Run submission crypto depends on RSA key files from `config/kado.php` (`KADO_RSA_PRIVATE_KEY_PATH`, `KADO_RSA_PUBLIC_KEY_PATH`).
- Public RSA key is injected into `window.Kado.public_key` in `resources/views/layouts/default.blade.php`; game clients use it to encrypt run payloads.
- A new setting of the site goes in the settings table (`App\Settings\*`: Site, AntiCheat, Replays, Clans; a migration in `database/settings`, a field on its admin page « Paramètres »), not in `config/kado.php` (what depends on the server only: paths, binaries, queue, debug tools). Tests change them with `$this->setSettings(Class::class, [...])` (`Tests\TestCase`).
- Admin panel (Filament, `/admin`) UI must be in **French**: every user-facing string in `app/Filament/`, `app/Livewire/` admin widgets and `resources/views/filament/` (labels, headings, notifications, options, tabs). Always set an explicit French `->label()` on fields/columns (Filament otherwise derives English labels from column names) and `$modelLabel`/`$pluralModelLabel` on resources. Code identifiers stay in English.
- Forum of the site = the forum of Eternaltwin (category `ETERNALTWIN_FORUM_CATEGORY`, `/forum`): called server-side through `App\Http\Controllers\Api\EtwinForumController` (Eternaltwin sends no CORS headers) with the player's Eternaltwin token stored at login (`users.etwin_access_token`, encrypted; scope `ETERNALTWIN_SCOPE`, `forum:write` only once the app is allowed it on Eternaltwin or the login is refused). Posts come as HTML rendered by Eternaltwin; the editor previews with the grammar it serves (`section.self.grammar`), icons in `public/gfx/forum/etwin`. Local Eternaltwin = upstream `main` built by `docker/eternaltwin/Dockerfile` (`ETERNALTWIN_REF` in compose.yaml, DB `etwin_main.dev`).
- Replay comments and views (`App\Services\RunCommentService`, `App\Services\RunViewService`, `RunCommentController`): plain-text comments at a frame of the replay (answers on one level, likes), loaded all at once by the replay page (`resources/js/pages/runs/show.vue`, `resources/js/components/runs/comments`); their marks are drawn in the progress bar of the game and the comment reached above its controls on a computer (`KadoKadeoManager.setReplayMarkers` / `setReplayComment`, `ReplayHud`, key C hides them; followed by `useReplayClock`: rebuild the games after changing them). Counters kept on the rows (`runs.views_count` / `comments_count`, `run_comments.likes_count`): one view by player after `view_after_seconds` really played. Limits in the settings table (`App\Settings\ReplaySettings`, admin « Paramètres > Replays »), not in the env. Admin: page of a run (`RunResource` view, tab « Commentaires »).
- Reports (« Signaler ») and the queue « Modération > Signalements »: `App\Services\ReportService`, `App\Contracts\Reportable`; make a content reportable with `.opencode/skills/reporting/SKILL.md`.
- Scheduled commands are defined in `routes/console.php` and executed by container cron (`docker/app/conf/crontab` runs `artisan schedule:run` every minute).
- Production (no Docker): one systemd service only, `php artisan kado:worker` (`App\Console\Commands\RunWorker`: `queue:work` + `reverb:start` as children, started again when they stop; stopping them is left to systemd `KillMode=control-group`). A new long-running process goes in it, not in a new service (README « Production worker »).
- Clans on/off: `ClanSettings::$enabled` (admin « Paramètres > Clans », off by default). New clan API routes go inside the `EnsureClansAreEnabled` group of `routes/api.php`, new clan pages get the `clans` router middleware; the front reads `window.Kado.clans_enabled` (`useClanStore().enabled`). The admin manages the clans either way; tests of the clans use `Tests\Concerns\EnablesClans`.
- Clan forum (`App\Services\ClanForumService`, `/api/clans/{clan}/forum`) and private messages (`App\Services\MessageService`): texts are stored as raw Marktwin and rendered client-side only (`resources/js/marktwin/render.js`: `useMarktwin` on the site, `<kado-marktwin text>` in the admin via `resources/js/admin/marktwin.js` loaded by a Filament render hook; grammar in `resources/js/marktwin/grammar.js`). Admin « Modération > Messages privés »: every message, and the system messages (signed KadoKado) to a player or to all. The `@eternaltwin/marktwin` 0.6.0 WASM panics (and corrupts its memory) on non-ASCII input: `useMarktwin` sends it ASCII only (entities put back after). It is loaded through `vite-plugin-wasm`, whose dev helper `/__vite-plugin-wasm-helper` must be proxied to Vite (`docker/app/conf/kadokadeo.conf`).

## Front-end Styles

- Colours, fonts, shadows, animations: the `@theme` of `resources/css/app.css` only (the palette `kado-*`, from `public/assets/original_style.css`; a colour that is not in it says where it comes from). No hex in the classes, no default palette of Tailwind (`text-gray-500`...).
- No `<style>` in the components, no global class, no `!important`: Tailwind utilities. A look shared by several components: `@utility` in `app.css` when it styles the element itself (`kado-page-title`, `game-interface-1`), `@layer components` when it reaches its children or gives default margins (`.kado-table`, `.kado-notice`), under the utilities so that the classes of a page win.
- `@layer base` styles the document only (`html`, `body`, `a`, `img` inline): nothing by tag. The looks of KadoKado are components in `resources/js/components/kado/` (`KadoPageTitle`, `KadoSectionTitle`, `KadoTable`, `KadoSideBox`, `KadoNotice`) and `form/` (`FormButton`, `FormInput`...): use them rather than raw tags.
- A component sets no outer margin as a utility (it would beat the `space-y` of its parent): the page places it.
- Karbon (`<html data-theme="karbon">`): the `karbon:` variant, in the components.
- Checked by `npm run lint:css` (`scripts/lint-css.mjs`, in the CI).
